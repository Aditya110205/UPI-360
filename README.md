# UPI 360: Growth, Behaviour and Risk

An end-to-end analysis of India's UPI payments, built from 114 months of monthly NPCI statistics (Apr 2017 to Sep 2026). It covers cleaning, a SQL layer, statistics, a holdout-tested forecast, anomaly detection and an interactive dashboard.

## What it answers

1. **Market:** How fast has UPI grown, and is growth slowing?
2. **Behaviour:** Is there seasonality once the growth trend is removed, and how has ticket size changed?
3. **Risk:** Which months broke from their own trend?

## Key results

All numbers are generated by the code in this repo (see `KEY_METRICS.md`).

| Area | Result |
|---|---|
| Volume | 7.2M (Apr 2017) to 24,068M transactions (Sep 2026); record 24,509M in Aug 2026 |
| Growth | 136.7% CAGR over 9.4 years; year-on-year growth slowed from 225% (2019 average) to 25% (last 12 months) |
| Banks live | 48 to 756 |
| Ticket size | Average payment fell from Rs 3,154 to Rs 1,220 (-61%), so growth came from smaller payments |
| Seasonality | With the trend removed, Oct to Dec runs 7.5% above other months (p < 0.001); December strongest, June weakest |
| Forecast | On a 6-month holdout, a 12-month drift model scored 2.20% MAPE vs 3.65% for a naive baseline and 2.48% for damped ETS |
| Phases | Launch and ramp-up (15 months), Scale-up (39), Mature (60) |
| Anomalies | 6 flagged months, including April and May 2020 (lockdown dip and rebound) |

## Dashboard

Five views: Market, Behaviour, Forecast, Risk and Ask the Data, with a date-range filter.
Ask the Data answers common questions from the data using rules. It does not call an AI model.

Open `dashboard/index.html` in a browser, or run it through Streamlit (see below).

## How to run

```bash
# 1. Setup
python -m venv .venv
.venv\Scripts\Activate.ps1        # Windows (use: source .venv/bin/activate on Mac/Linux)
pip install -r requirements.txt

# 2. Build the pipeline
python src/clean.py               # raw data -> DuckDB
python src/models.py              # forecast, phases, anomalies
python src/metrics.py             # KEY_METRICS.md and RESUME_BULLETS.md
python src/build_dashboard.py     # dashboard/index.html

# 3. View the app
streamlit run app/app.py          # http://localhost:8501
```

`models.py` needs the `upi_monthly` table that `clean.py` creates and stops with an error if it does not find 114 months.

## Method notes

- **Forecast:** Three models trained up to Mar 2026 and tested on Apr to Sep 2026. The best one is refit on all data for the next six months. The range shown is approximate, based on recent monthly volatility.
- **Seasonality:** Each month is divided by its centred 12-month average before comparing, because raw month averages mostly reflect which years a month appears in. Oct to Dec is tested against the rest with Mann-Whitney.
- **Phases:** K-means (k=3) on log volume.
- **Anomalies:** Isolation Forest on how far each month's volume growth and ticket-size change sit from their trailing 12-month median. The top 6% are flagged, starting from May 2018, once a year of history exists.

## Limitations

- The data is monthly national totals. There are no users, merchants or individual transactions, so behaviour findings describe the market, not people, and this is not a payment-fraud model.
- Anomalies mean unusual months, not errors or fraud.
- The forecast assumes the recent trend continues and cannot anticipate policy changes.
- Ask the Data handles a fixed set of question types.
